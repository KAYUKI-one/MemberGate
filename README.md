# 注册与权限管理（MemberGate）

Typecho 插件，新增注册申请的审核，可以用 Telegram 处理注册申请。

两件事：

1. **注册要审核。** 换掉 Typecho 自带那个「填个用户名和邮箱就立刻建号」的注册页。
   新流程要填用户名、邮箱、密码、**注册原因**，同时记下 IP、时区、浏览器、来源，
   申请推到你的 **Telegram**，你点一下按钮才建账号。审核之前申请人**根本没有账号**。
2. **整篇文章可以只给注册用户看。** 写文章时把「仅注册用户可见」选成「是」，
   未登录访客在首页、分类、标签、搜索、订阅里都看不到它，直接访问文章链接返回 404。

**不需要改主题一个字**，也不需要站点能被外网访问。

---

## 一、安装

1. 把 `MemberGate` 整个目录放进 `usr/plugins/`
2. 后台 **控制台 → 插件**，找到「注册与权限管理」，点启用
   - 启用时会自动建一张表 `typecho_member_requests` 存申请记录
3. 进它的 **设置** 页，填 Telegram 那两项，保存

启用后左侧菜单会多出 **「注册审核」** 一项。

---

## 二、配 Telegram

只需要两样东西：一个 bot token，一个 chat id。**不用配 webhook，不用公网地址**。

### 1. 建 bot，拿 token

Telegram 里找 **@BotFather** → 发 `/newbot` → 按提示起名字 → 它会给你一串
`123456789:AAE...` 这样的 token。填到设置的「Telegram Bot Token」。

### 2. 拿 chat id

**最省事的办法（推荐，不碰任何东西）：**

1. 在 Telegram 里搜 **@userinfobot**，给它随便发一句话
2. 它回的信息里有一行 `Id: 123456789`，那串数字就是你的 Telegram 用户 id，
   也就是你和 bot 私聊时的 chat id
3. 把这串数字填到设置的「Telegram Chat ID」，保存

想推到**群**里：把 @userinfobot 拉进群（或者在群里 @ 它一下），
它会回一个**负数**的 id，那个就是群的 chat id。拿到之后把这个 bot 踢出去就行。

### 2.5 推送到群（顺便不暴露个人 id）

私聊的 chat id 等于你的**个人账号 id**，永久且改不掉。如果不想把这串东西存进
站点数据库，就推到一个只有你和 bot 的群里 —— 存的是群的负数 id，
跟你个人账号没有对应关系。

1. **建群**：Telegram → 新建群组 → 在选成员的搜索框里搜你 bot 的用户名 → 选中它 →
   起个名 → 创建。群里就只有你和它两个。
   （有的客户端那个搜索框不搜用户名，那就先随便拉个人建群，建完再把那人移除。）
2. **让 bot 在群里"看见"一条消息** —— 这步最容易漏。Telegram 的 bot 默认开着
   privacy mode：在群里它**收不到**普通聊天内容，只收「命令」和「@它的消息」。
   所以在群里发一句 `/start@你的bot用户名`（或者 `@你的bot用户名 hi`）。
3. **拿 id**：后台 **注册审核** → **「拉取最近会话」** → 列表里会出现群名和一个
   **负数** id（`-100…` 是超级群，`-…` 是普通群），填进设置。

**第 3 步要求这个 bot 没有挂着 webhook**（webhook 和 `getUpdates` 互斥）。
如果你的 bot 挂着，点「拉取最近会话」时插件会告诉你 webhook 指向哪、队列里压了多少条，
并让你改用 @userinfobot。**插件不会自己去删你的 webhook**：删掉会把待处理队列一起清空，
排在后面的那个服务就永远收不到那些消息了。

顺带一提：如果你**不认识**那个 webhook 地址，那可能意味着 bot token 泄露过，
建议去 @BotFather 用 `/revoke` 换一个新 token。

**另一条路：让插件自己去问 bot（私聊版）**

1. 在 Telegram 里找到你建的 bot，**给它随便发一句话**（比如 `hi`）
2. 回到后台 **注册审核** 页，点 **「拉取 bot 最近会话」**
3. 页面上会列出你的 id，填进设置里

### 3. 验一下

回到 **注册审核** 页，点 **「发一条测试消息」**。Telegram 收到就说明通了。

> 没配 Telegram 也能用 —— 申请照样存下来、后台照样能审，只是你收不到提醒，
> 得自己隔三差五去「注册审核」页看一眼。页面顶部会一直提醒你这件事。

## 三、注册是怎么走的

### 申请人那边

1. 点站上任何一处「注册」（页头、页脚、图片锁的占位块……）——
   这些链接原本都指向 Typecho 自带的 `/admin/register.php`，
   插件在 HTTP 层把它们统一引到自己的表单页
2. 填用户名、邮箱、密码、确认密码、**注册原因**（时区由浏览器自动带上）
3. 提交后拿到一个 **「查询进度」链接**，页面会提示**收藏它**

**审核结果不发邮件。** 申请人靠两样东西知道结果：

- 那个查询链接 —— 随时点开，显示「审核中 / 已通过 / 未通过」
- 去登录时的提示 —— 没通过审核的账号去登录，会明确告诉他「申请还在审核中」，
  而不是让人一脸问号地看到「用户名或密码无效」

### 你那边

Telegram 会收到一条消息，用户名、邮箱、注册原因、IP、时区、浏览器、来源、时间全在里面，
**消息下面挂着「✅ 通过」「❌ 拒绝」两个按钮**。点一下就审完了 ——
不需要先登录后台，链接带一次性凭据，点过就作废，再点会提示「已经处理过了」。

不想用 Telegram 的按钮也行：后台 **注册审核** 页有完整的列表，
可以填一句备注再通过/拒绝，也能翻「已通过 / 已拒绝」的历史。

**通过的那一刻才真正建账号**（用户组 `subscriber`），密码就是申请人自己设的那个。
备注（如果填了）会显示在申请人那个查询页面上，拒绝时尤其有用。

## 四、锁整篇文章

写文章 / 写页面的右侧 **「自定义字段」** 里多了一项 **「仅注册用户可见」**，选「是」就行。

未登录访客：

| 位置 | 表现 |
| --- | --- |
| 首页 / 分类 / 标签 / 日期 / 作者归档 | 没有这篇文章，卡片都不出现 |
| 搜索 | 搜不到 |
| RSS / Atom 订阅 | 没有 |
| 直接打开文章链接 | **404** |
| 相邻文章的上一篇/下一篇导航 | 标题显示为「仅注册用户可见」，链接点进去 404 |

登录**且已通过审核**的账号：正常显示，和普通文章没区别。

管理员、编辑、贡献者始终能看到 —— 那是后台干活的人，不受影响。

所以「审核通过」这件事的含金量就是：**一个账号从什么都看不到，变成能看到这些文章。**

## 五、几件得提前知道的事

### 1. 锁的是「拿不到」，不是「加密」

这一层是在**数据库查询**上做的：锁定的文章根本不会进访客拿到的 HTML，
不是前端盖一层遮罩。所以 F12、查看源代码、禁用 JS 都翻不出来。
但它拦的是「顺手看到」，不是密码学意义上的保密 —— 能登录到数据库的人当然还是能看到。

### 2. 这几处不在管辖范围内

- **附件直链**：文章里的图片文件本身如果 URL 被人拿到，直接打开还是能看到。
  要真正做到私有得用对象存储的签名 URL，那是存储层的事。
  （正文里某几张图想单独锁，用旁边的 `MemberOnlyImages` 插件。）
- **相关文章**：Typecho 的 `Widget\Contents\Related` 是自己拼的查询，不经过本插件。
  本主题（acg-gallery）没有用到它，所以实际不影响；换了主题要留意。
- **XML-RPC**：需要用户身份的接口不受影响；匿名能调的接口本来就拿不到非公开内容。

### 3. 查询链接别丢

申请人那边唯一的凭据就是那个链接。丢了的话，让 TA 用同样的名字/邮箱**重新提交**会被
「用户名已经存在」挡下来 —— 那是故意的，防止有人拿别人的名字反复占位。
真丢了就让 TA 直接找站长，你在后台「注册审核」里能看到全部记录。

### 4. 待审的申请会占住用户名和邮箱

有人提交了申请但还没过审，那个用户名和邮箱就被占住了，别人不能再提交同样的。
这是有意的：不然会出现「审核通过那天名字被人抢了」。

同一个人**重复提交**也会被挡（用户名或邮箱重复）。想改内容，就让 TA 换名字重提，
或者你直接在后台处理掉那条。

### 5. 同 IP 待审上限

默认同一个 IP 最多同时压 3 条待审申请，超了直接拒绝，防止有人刷。
设置里可以调，填 `0` 表示不限制。

### 6. 开了页面缓存要当心

如果站上装了缓存插件、或者 CDN 缓存了 HTML，必须确认**登录用户的页面不被缓存**。
否则缓存下来的「访客版本」可能被发给已登录用户。Typecho 本身不缓存页面，
装了插件才需要留意。

### 7. 邮件那块默认是关的

设置页下半部分有一组「【可选】」开头的邮件项。**全留空就完全不发邮件**，一点不影响功能。
你有能发信的邮箱（SMTP）时填上，申请会同时抄送一份到那个邮箱，等于多个备份通道。
两个渠道一个失败不影响另一个，只要有一个成功就算通知到了。

## 六、和「图片权限锁」的关系

两个插件互不干涉，可以同时开：

| | `MemberOnlyImages` | 本插件 |
| --- | --- | --- |
| 管什么 | 正文里**某几张图** | **整篇文章** |
| 怎么标记 | 图片地址末尾加 `#member` | 写文章时选「仅注册用户可见」 |
| 未登录看到 | 那几张图连位置一起消失（默认档位） | 文章整个不存在 |
| 生效层 | 正文渲染的输出过滤 | 数据库查询 |

两边默认都是「静默移除」：未登录访客拿到的 HTML 里没有任何痕迹。
`MemberOnlyImages` 也保留了「占位提示块」档位，如果你把它打开，
块里的「注册」按钮会走到本插件的注册页 —— 那个链接用的是 `$options->registerUrl`，
正好被本插件接管了。

## 七、实现说明

### 为什么「文章锁」必须做在查询层

主题的 `post.php:7` 会直接输出「首页缩略图」字段当顶部大图，**这发生在正文过滤器之前**。
所以只过滤正文（像 `MemberOnlyImages` 那样挂 `contentEx`）会漏掉题图。
要真锁住，只能在 `Widget\Archive` 把文章查出库之前就把它排除掉。

具体挂在 `Widget\Archive` 的 `handleInit` 上（`var/Widget/Archive.php:651`），
时机是 select 拼完之后、各种 handle 之前 —— 首页 / 分类 / 标签 / 搜索 / 日期 / 作者 /
单篇 / 订阅全都覆盖到了。加的条件是：

```sql
table.contents.cid NOT IN (1, 2, 3)
```

锁定文章的 cid 每次请求查一次、静态缓存。**这里不能写子查询** ——
Typecho 的 `Query::filterColumn` 会把 `SELECT` / `FROM` / `WHERE` 当成列名加上反引号
（`Query::KEYWORDS` 里只有 `AND|OR|LIKE|IN|NOT|IS|NULL` 这些），子查询会被拆坏。

单篇为什么是 404：`singleHandle` 查到 0 行时，核心自己会抛
`WidgetException(_t('请求的地址不存在'), 404)`（`var/Widget/Archive.php:1664`），不用另外写。

相邻文章导航（`thePrev()` / `theNext()`）是自己拼的查询、不走 `handleInit`，
所以在 `Widget\Base\Contents` 的行过滤器里把锁定文章的标题换成占位文字。
链接本身会 404，地址不算漏。

### 为什么注册页能顶掉自带的

主题里所有「注册」链接都指向 `$options->registerUrl`，也就是 `/admin/register.php`。
这个 URL 由 `Widget\Options::___registerUrl()` 生成，插件改不了
（`Widget::__get` 遇到同名方法就优先走方法，钩子够不着）。

所以改在 HTTP 层拦：`admin/common.php` 每个后台页面都会触发 `begin` 钩子
（`admin/common.php:18`），而 `admin/register.php` 第一件事就是 `include 'common.php'`。
判断文件名是 `register.php` 就跳走，**主题一个字都不用动**。

### 账号状态怎么表示

申请人在过审前**没有 `table.users` 记录**，所以「还没过审」不需要额外的用户组 ——
登录不上、拿不到任何权限是天然结果。

过审后建号用的用户组是 `subscriber`。`Widget\User::pass('subscriber', true)`
对 administrator / editor / contributor / subscriber 为真，对 `visitor`（组表里排第 4 位）
为假 —— 正好就是「已通过审核的人」。以后要加新组、调组权重，两处判断都不用动。

### 三个凭据，各管各的

| 凭据 | 用在哪 | 什么时候失效 |
| --- | --- | --- |
| 表单 CSRF | `md5(secret + salt)` | 换 secret 就失效 |
| `token` 列 | Telegram / 后台的审核链接 | 审核完立刻换掉，一次性 |
| 查询 token | 申请人的进度查询链接 | **不过期**，HMAC(id + created, secret) 算出来的，不落库 |

审核链接和查询链接**必须分开**：前者要在审完就作废，后者要一直有效。
查询 token 用 HMAC 而不是存一列，是因为它得和登录状态无关 ——
申请人换个设备、退出登录之后还得能查。

### 文件

```
Plugin.php            钩子注册、设置面板、文章锁、登录提示
Model.php             申请表：建表 / 增删查改 / 查重 / 限流
Notifier.php          通知站长：Telegram（主）+ 邮件（备选）
Mailer.php            发信：SMTP 或 PHP mail()
Widget/Register.php   /action/memberregister：表单页 / 提交 / 查询 / 审核 / Telegram 工具
Admin/Panel.php       后台「注册审核」菜单页
```

发 Telegram 优先用 curl，没有 curl 就退回 `file_get_contents` ——
虚拟主机上两者总有一个能用。两个都被禁了会在后台明确告诉你，而不是默默失败。
